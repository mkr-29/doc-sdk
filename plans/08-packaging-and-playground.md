# Plan 08: Packaging, Distribution & Interactive Demo Playground

## Objective
Finalize the SDK bundle build via `tsup` (generating ESM, CJS, and `.d.ts`), verify package subpath exports, and construct an interactive demo playground application showcasing the full builder -> editor -> renderer lifecycle in real time.

---

## 1. Deliverables & Files
- `index.ts`: Root SDK barrel export (`core`, `admin`, `client`, `hooks`).
- `tsup.config.ts`: Multi-entry build configuration producing:
  - `dist/index.mjs`, `dist/index.cjs`, `dist/index.d.ts`
  - `dist/core/index.mjs`, `dist/core/index.d.ts`
  - `dist/admin/index.mjs`, `dist/admin/index.d.ts`
  - `dist/client/index.mjs`, `dist/client/index.d.ts`
  - `dist/hooks/index.mjs`, `dist/hooks/index.d.ts`
  - `dist/styles.css`
- `playground/`: Interactive web app runnable locally via `npm run dev`:
  - Tab 1: Template Builder (design template, switch sample presets).
  - Tab 2: Content Form Editor (create/edit doc content with dynamic inputs).
  - Tab 3: Client Viewer (live rendered doc with interactive layout toggle).
- `tests/integration/e2e-workflow.test.tsx`: Automated integration test verifying that a template generated by `TemplateBuilder` can be filled in `DocContentEditor` and rendered in `DocRenderer`.

---

## 2. Automated Test Suite (`tests/integration/e2e-workflow.test.tsx`)
1. Create a `DocTemplate` via builder logic.
2. Initialize `DocContent` with the template.
3. Add a markdown block and an API endpoint block.
4. Pass both objects into `<DocRenderer/>`.
5. Assert that the rendered DOM contains the markdown content, the API endpoint badge, and the sticky layout elements.

---

## 3. Automated Gatekeeper Command
```bash
npm run test && npm run typecheck && npm run build
```
- Assert that `dist/` contains all expected entry points and TypeScript `.d.ts` declaration maps without compilation errors.
